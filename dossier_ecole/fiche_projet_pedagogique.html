1. Le problème et la solution

1.1 Contexte médical

L'interprétation d'un électrocardiogramme (ECG) est une compétence fondamentale en médecine, évaluée aux Épreuves Dématérialisées Nationales (EDN). Aujourd'hui, l'évaluation repose sur des QCM simplifiés ou des corrections manuelles chronophages. Aucune solution ne permet d'évaluer automatiquement un texte libre rédigé par un étudiant et de produire un feedback pédagogique individualisé ancré dans le cours officiel.

1.2 Notre solution

Edu-ECG est un pipeline de Retrieval-Augmented Generation (RAG) neurosymbolique qui transforme le texte libre d'un étudiant en une note structurée sur 100% avec un feedback personnalisé.

Le terme neurosymbolique traduit la combinaison de :

  • Raisonnement symbolique : ontologie OWL avec 345 concepts, relations sémantiques et règles d'inférence déterministes
  • Inférence neuronale : GPT-4o (extraction), GPT-4o-mini (jugement, feedback), text-embedding-3-small (recherche vectorielle)

1.3 Exemple concret

ENTRÉE — Texte libre de l'étudiant

« rythme sinusal, 70 bpm, BBD complet, pas de trouble de repolarisation »

SORTIE — Évaluation automatique

✅ Rythme sinusal — exact ✅ BBD complet — exact ⚠️ Bloc de branche droit — déduit (enfant trouvé) ❌ Hypertrophie ventriculaire droite — manqué
Score : 78/100   + Feedback pédagogique (150-300 mots, ancré cours SFC)

1.4 Cadre académique

Le projet s'inscrit dans le cadre d'un mémoire de Master 2 en cardiologie. Il combine pédagogie médicale, IA médicale et ingénierie ontologique. Le référentiel pédagogique est le chapitre 15 du cours SFC (Item 231 EDN, CNEC 2e édition), intégré sous forme de 33 entrées couvrant 85 concepts ontologiques.

Détail de chaque brique

🧱 Brique 0 — Socle Ontologique & Index Vectoriel

L'ontologie OWL (345 concepts) est convertie en 658 documents (1 canonique + N synonymes par concept), encodés via text-embedding-3-small (vecteurs 1536 dimensions) et indexés en BM25. Cette brique s'exécute une seule fois quand l'ontologie change.

🧱 Brique 2 — Extraction NER (V2)

GPT-4o avec Structured Outputs (schéma Pydantic) extrait les termes cliniques du texte libre. 7 règles guident l'extraction : zéro normalisation, périmètre ECG large, gestion de la négation, méthode LEGO (modificateurs séparés), conversion des valeurs numériques, expansion des abréviations (V2), et reformulation morphologique (V2).

Un filet de sécurité regex post-NER détecte les négations ratées par le LLM ("pas de trouble de repolarisation").

🧱 Brique 3 — Recherche Hybride

Chaque terme NER est recherché simultanément via embeddings cosinus (sémantique) et BM25 (lexical). Les résultats sont fusionnés par Reciprocal Rank Fusion (RRF) avec boost pour les acronymes BM25. Un helper _deflect() gère les flexions singulier/pluriel et masculin/féminin.

🧱 Brique 4 — Juge Neurosymbolique

Deux étapes :

  1. Coupe-circuit (~42% des cas) : si le terme normalisé matche exactement une forme de surface → résolution déterministe, 0 token LLM.
  2. Juge LLM (~58%) : GPT-4o-mini résout un QCM contraint parmi les Top-K candidats. Validation post-LLM : si l'ID renvoyé n'est pas dans les candidats → forçage NONE.

🧱 Brique 5 — Scoring V3 Ontologique

Score déterministe exploitant la hiérarchie parent/enfant, les relations requires, supports, excludes et has_qualifiers. Détaillé en Section 6.

🧱 Brique 6 — Rapport + Feedback Pédagogique (V2)

Feedback en 2 sections : (1) Référence au cours SFC Item 231 avec citations et rangs EDN, (2) Commentaire personnalisé sur l'interprétation de l'étudiant. Export HTML standalone.

Stratégie clé : le LLM ne voit jamais l'ontologie

Le LLM ne voit jamais l'ontologie complète. Il ne reçoit que les Top-K candidats pré-filtrés par la recherche hybride. Il ne peut pas inventer un ID ontologique — la validation post-LLM est stricte. Le scoring est 100% symbolique et reproductible.

3. L'ontologie ECG — Ce qu'elle représente

3.1 Vue d'ensemble

L'ontologie est le cœur symbolique du système. Modélisée en OWL (Web Ontology Language) via WebProtégé, elle structure l'ensemble des concepts de l'interprétation ECG dans un arbre hiérarchique à 8 niveaux de profondeur.

Concepts

Synonymes

Documents RAG

Profondeur max
8
niveaux dans l'arbre

3.2 Que contient-elle ?

Chaque concept de l'ontologie représente un élément de l'interprétation ECG : un signe observable, un diagnostic, un qualificateur, ou une localisation anatomique. Par exemple, BLOC_DE_BRANCHE_GAUCHE_COMPLET est un diagnostic composé d'un parent (Bloc de branche gauche), de synonymes (BBG complet, BBGc, cLBBB), et de relations sémantiques (supports: QRS ≥ 120 ms).

3.3 Les 4 types de concepts

TypeNbRôleExemples
finding 146 Signe ECG observé QRS large, Tachycardie, Onde Q
qualifier 106 Modificateur d'un concept Complet, Incomplet, Rapide, Type 1
pattern 53 Diagnostic composite ECG normal, BBD complet, FA
topography 40 Localisation anatomique Antéro-septal, Latéral, Apex

3.4 Les catégories cliniques (pondération du score)

Chaque concept est classé dans une catégorie clinique qui détermine son poids dans le score :

CatégorieNbPoidsExemples

DIAGNOSTIC_MAJEUR 884 BBD complet, FA, Flutter

3.5 Les 5 relations sémantiques

Ce qui distingue cette ontologie d'un simple dictionnaire, ce sont ses relations sémantiques exploitées par le scoring :

RelationNbSémantiqueExploitée par
parents345 Hiérarchie is-a (ex: BBD_COMPLET → BLOC_DE_BRANCHE_DROIT) Scoring V3 : enfant trouvé = 1.0, parent = 2/3
requires68 Ce concept nécessite ces findings Scoring V3 : nb_req_trouvés / nb_req_total
supports47 Élément supportant (pas obligatoire) Scoring V3 : score partiel 1/3
excludes49 Incompatible avec… Scoring V3 : score → 0. Négation → concept positif
has_qualifiers94 Qualificateurs de ce pattern Scoring V3 : score partiel 2/3

3.6 Exemple concret : le concept BLOC_DE_BRANCHE_GAUCHE_COMPLET

Voici comment un concept est structuré dans l'ontologie :

CONCEPTS_ECG
  └── TROUBLE_DE_LA_CONDUCTION
      └── BLOC_DE_BRANCHE
          └── BLOC_DE_BRANCHE_GAUCHE [poids 3, DIAGNOSTIC_MOYEN]
              └── BLOC_DE_BRANCHE_GAUCHE_COMPLET [poids 3, DIAGNOSTIC_MOYEN]
synonymes → "BBG complet", "BBGc", "cLBBB"
parent → BLOC_DE_BRANCHE_GAUCHE
supports → QRS ≥ 120 ms
has_qualifiers → QRS_LARGE
type → qualifier

Le concept parent BLOC_DE_BRANCHE_GAUCHE a lui-même une relation excludes → BLOC_DE_BRANCHE_DROIT (ces deux diagnostics sont mutuellement exclusifs) et des enfants : BBG complet et BBG incomplet.

3.7 Ce qu'aucun standard ne fait

À notre connaissance, il n'existe pas d'ontologie ECG francophone orientée évaluation pédagogique avec relations sémantiques (requires / excludes / supports) et scoring intégré. SNOMED CT est une terminologie (~350 000 concepts, toute la médecine) sans pondération ni scoring. HL7 aECG et SCP-ECG sont des formats de signaux, pas d'interprétation textuelle.

5. Trace complète du pipeline sur le cas

Suivons chaque terme de l'étudiant à travers les 4 briques actives du pipeline :

🧱 Brique 2 — NER (GPT-4o, Structured Outputs)

GPT-4o reçoit le texte libre et extrait 8 entités cliniques. Les abréviations sont développées (RS → Rythme sinusal, BBG → Bloc de branche gauche) grâce aux règles V2.

BBGpresent
completpresent
Déviation axiale gauchepresent

trouble de la repolarisation appropriépresent

⚙️ Méthode LEGO : "BBG complet" est décomposé en 2 entités : "BBG" + "complet" (règle 4 du prompt NER).

🧱 Briques 3 & 4 — Recherche Hybride + Juge Neurosymbolique

Chaque terme est recherché dans l'index vectoriel (658 documents). Le coupe-circuit résout 6 termes sur 8 sans appel LLM. Les 2 restants passent au juge GPT-4o-mini.

RS → RYTHME_SINUSAL coupe-circuit cos=0.848 exact ✓
Normocarde → FREQUENCE_NORMALE coupe-circuit cos=0.929 exact ✓
BBG → BLOC_DE_BRANCHE_GAUCHE coupe-circuit cos=0.885 exact ✓
complet → BLOC_DE_BRANCHE_GAUCHE_COMPLET juge LLM confiance=85
Déviation axiale gauche → DÉVIATION_AXIALE_GAUCHE coupe-circuit cos=0.882 exact ✓
PR normal → PR_NORMAL coupe-circuit cos=0.915 exact ✓
trouble de la repolarisation approprié → TROUBLE_DE_REPOLARISATION juge LLM confiance=90
QT normal → QT_NORMAL coupe-circuit cos=0.886 exact ✓
Résumé : 6 coupe-circuit 2 juge LLM — Le coupe-circuit a résolu 75% des termes sans appel LLM (déterministe, gratuit, instantané).
🔬 Focus : comment "complet" devient BLOC_DE_BRANCHE_GAUCHE_COMPLET

Le terme "complet" est ambigu : il pourrait désigner BBD complet, BBG complet, ou BAV complet. La recherche hybride retourne les Top-3 candidats suivants :

#CandidatScore RRFCosinus
1 BLOC_DE_BRANCHE_DROIT_COMPLET 0.0413 0.518
2 BAV_COMPLET 0.0406 0.465
3 BLOC_DE_BRANCHE_DROIT_COMPLET 0.0397 0.467

Le juge GPT-4o-mini reçoit ces candidats + le contexte (le terme précédent "BBG" dans le texte) et choisit BLOC_DE_BRANCHE_GAUCHE_COMPLET avec confiance 85. C'est la compréhension contextuelle du LLM qui fait la différence : "BBG" + "complet" → BBG complet, pas BBD complet.

6. Scoring V3 — Comment le score est calculé

6.1 L'algorithme

Pour chaque concept attendu (golden), le scoring cherche la meilleure correspondance parmi les concepts trouvés :

PrioritéConditionScore
1Match exact ou synonyme1.0
1bUn enfant (descendant) trouvé1.0
1cUn parent direct trouvé (distance 1)2/3
1cUn parent éloigné trouvé (distance ≥ 2)1/3
2Non trouvé, mais requires partiellement satisfaits0..1 (ratio)
3Non trouvé, has_qualifiers trouvés2/3
4Non trouvé, supports trouvés1/3
5Un excludes trouvé0 (écrase tout)
6Rien trouvé0

6.2 Application au cas 10 (BBG complet)

L'étudiant a fourni 8 concepts. Le golden set en attend 3. Voici le calcul :

BLOC_DE_BRANCHE_GAUCHE_COMPLET
1.0

→ L'étudiant a trouvé le concept exact via "BBG" + "complet" (enfant trouvé = 1.0)

RYTHME_SINUSAL
1.0

→ "RS" → coupe-circuit → RYTHME_SINUSAL (match exact)

PR_NORMAL
1.0

→ "PR normal" → coupe-circuit → PR_NORMAL (match exact)

Score final = (1.0 + 1.0 + 1.0) / 3 × 100 = 100%
Les 5 autres concepts trouvés (Normocarde, Déviation axiale gauche, etc.) ne sont pas dans le golden set mais enrichissent le feedback — l'étudiant démontre une analyse complète.

7. Forces du système

#ForceDétail
F1 Architecture neurosymbolique rigoureuse Séparation symbolique/neuronal. Le LLM ne voit jamais l'ontologie complète. Le scoring est 100% déterministe et reproductible.
F2 Ontologie ECG unique et spécialisée 345 concepts, 5 types de relations sémantiques, 318 synonymes français. Pas d'équivalent francophone orienté évaluation.
F3 Scoring V3 hiérarchique Exploite hiérarchie parent/enfant, requires récursifs, excludes. Dépasse le simple match binaire.
F4 Tolérance fautes et abréviations Embeddings + BM25 + RRF absorbent les fautes ("tachi supra"). NER V2 développe les acronymes courants.
F5 Feedback ancré dans le cours Citations du cours SFC Item 231, rangs EDN (A/B/C), commentaire du correcteur intégré.
F6 Coût maîtrisé ~$0.02/cas, ~$13 pour 645 évaluations. Aucune GPU locale requise.
F7 Gestion de la négation Double filet (prompt NER + regex Python) pour capturer "pas de trouble de repolarisation".
F8 Coupe-circuit déterministe 42% des résolutions sans LLM : matching exact normalisé → gratuit, instantané, reproductible.

8. Limites connues et sujets de développement

Le système a des limites identifiées, qui constituent autant de sujets de développement pour des étudiants en ingénierie informatique.

AxeLimiteImpactSujet de développement
W1 Dépendance API OpenAI Pas de fallback local Évaluer des modèles locaux (Mistral, Llama 3) pour NER et juge. Benchmark coût/qualité.
W2 Recherche vectorielle non scalable Matrice NumPy en RAM (658 docs) Intégrer FAISS, Qdrant ou ChromaDB pour gérer >10K concepts.
W3 Ontologie non standardisée Pas d'alignement SNOMED CT Ajouter des mappings owl:sameAs vers SNOMED CT. Publier sur BioPortal.
W4 Golden set limité (15 cas) Biais de l'annotateur unique Étendre à 50+ cas avec annotations multi-experts et accord inter-annotateurs (Kappa).
W5 Pas de tests automatisés Régression non détectée Suite pytest couvrant négation, hiérarchie, synonymes. Intégrer en GitHub Actions CI.
W6 Couplage entre workspaces Sync manuelle du code Restructurer en monorepo avec packages Python installables (pip install -e).
W7 Pas de versionnement ontologie Pas de changelog structuré Adopter un format de diff ontologique avec versionnement sémantique.
W8 Diagnostic implicite (ECG normal) Sur-attribution si 1 composant sur 5 Implémenter des règles d'inférence pour les concepts compositionnels (requires ≥ N).
W9 Pas d'API temps réel Pipeline batch uniquement Exposer via FastAPI + interface web pour feedback en temps réel.
W10 Coverage EDN limitée (24.6%) 85/345 concepts couverts Étendre la knowledge base au-delà de l'Item 231 SFC.

Sujets prioritaires pour étudiants ingénieurs

🔴 Priorité haute
W5 — Tests automatisés
Écrire une suite pytest pour le scoring, le NER et le juge. Définir des cas de test (négation, hiérarchie, multi-niveaux). Intégrer en CI/CD GitHub Actions.
🔴 Priorité haute
W1 — Modèles locaux
Benchmark de Mistral-7B, Llama-3-8B en remplacement de GPT-4o-mini pour le juge. Évaluer le trade-off coût/qualité/latence.
🟡 Priorité moyenne
W9 — API temps réel
Exposer le pipeline via FastAPI. Interface web (React ou Streamlit) permettant à un étudiant de soumettre un texte et recevoir un feedback en <10s.
🟡 Priorité moyenne
W8 — Inférence compositionnelle
Implémenter un mécanisme d'inférence bottom-up : si ≥N composants d'un concept parapluie sont trouvés, inférer le concept parent.
